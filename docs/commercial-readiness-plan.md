# Commercial readiness plan

This is the later hosted-commerce track, not the Community 1.0 critical path. The canonical
[roadmap to 1.0](roadmap-to-1.0.md) now schedules a free Hosted Beta first and defers Stripe
until managed operations, tenant isolation, support, and real cost have been measured.

Status: developer preview, 2026-09-28. This is the release plan for Meerkateer Community and Meerkateer Cloud. A green unit suite or a polished website is not a production claim. Each phase closes only when its test cases pass in CI or a recorded release exercise, with a named owner and reproducible evidence. Cloud billing stays in sandbox until the final gate.

The first customer pilot now follows the narrower [Minecraft Java / Paper game-server beta](game-server-beta.md). Its G0–G5 slices supply the game-specific acceptance cases inside C2–C5 and C8; the commercial security, operations, and billing gates still apply.

## Release phases

| Phase | Deliverable and exit gate | Required test cases |
| --- | --- | --- |
| C0 — Repeatable baseline | Fresh install and upgrade reach the same schema; owner can always sign in with a password; setup key is limited to bootstrap and recovery. Contract, policy, lint, build, and full-stack tests pass. | C0.1 fresh PostgreSQL applies every migration in order; C0.2 upgrade from the previous schema preserves tenant/service data; C0.3 bootstrap rejects absent/short passwords; C0.4 password sign-in and recovery work; C0.5 setup-key sign-in endpoint is absent, including with a valid key. |
| C1 — Identity and tenant isolation | Cloud OIDC login, member invitation/removal, role rules, session revocation, audit trail, and gateway-wide throttling. Every API and worker path enforces tenant scope. Security review passes the selected OWASP ASVS controls. | C1.1 cross-tenant read/write and guessed-ID matrix; C1.2 OIDC state/nonce/PKCE and replay; C1.3 invite expiry, role change, revoked session; C1.4 CSRF and rate-limit across replicas; C1.5 audit of every privileged mutation. |
| C2 — Reliable status and history | Complete MKS/MKA event state machine, incident timeline, retention, quotas, and measurable freshness. Define Cloud capacity from benchmarks before selecting its storage profile. | C2.1 duplicate, conflicting, missing, and out-of-order events; C2.2 database/worker crash and replay without lost acknowledged data; C2.3 status transition and stale-state matrix; C2.4 retention and per-tenant quota; C2.5 representative load and latency report. |
| C3 — Agent and probes | Installable Linux/Windows agent, credential rotation, offline spool, bounded collectors, safe HTTP/TCP/DNS/TLS probes, signed configuration/update path. | C3.1 install/upgrade/uninstall on supported OS versions; C3.2 offline/restart/replay and credential expiry; C3.3 malformed and oversized input; C3.4 SSRF/DNS rebinding/private-address matrix; C3.5 safe update rollback and resource-budget soak. |
| C4 — Operator experience | Guided project/service onboarding, clear integration examples, actionable status and incident screens, usable mobile and keyboard flows, accessible labels and contrast. | C4.1 first-user browser journey through first heartbeat; C4.2 key creation/rotation/revocation and copy-once handling; C4.3 empty/error/recovery states; C4.4 keyboard and screen-reader review against WCAG 2.2 AA; C4.5 browser visual regression. |
| C5 — Alerts and operations | Durable webhook/email delivery, routing, deduplication, escalation basics, backups, restores, metrics, runbooks, and incident response. | C5.1 duplicate suppression, retries, dead-letter/replay; C5.2 failure/recovery alert timing; C5.3 restore a production-like backup and measure RPO/RTO; C5.4 DB/worker/network fault injection; C5.5 operator drill using runbooks. |
| C6 — Cloud commerce | Sandbox Checkout and Customer Portal, signed webhook inbox, idempotent entitlement projection, trial/grace/cancellation rules, usage and quota display. Community operates with billing entirely absent. | C6.1 valid/invalid webhook signature; C6.2 duplicate/reordered/delayed/missing events; C6.3 failed payment, renewal, cancellation, refund, and grace; C6.4 entitlement/tenant isolation; C6.5 Community boot and core features without Stripe. |
| C7 — Release assurance | Pinned and scanned dependencies, SBOM, signed images/provenance, supported upgrade/rollback path, TLS/deployment guides, privacy/terms/support commitments, independent security review. | C7.1 release artifact verification and vulnerability triage; C7.2 install/upgrade/rollback from supported prior release; C7.3 secret and config rotation; C7.4 penetration-test findings closed or accepted with owners; C7.5 legal/support docs reviewed. |
| C8 — Beta then GA | Controlled customer beta meets published SLO and support response targets; live billing is enabled only after Cloud operational and commerce gates pass. | C8.1 multi-day representative soak/load; C8.2 alert and backup/restore drills; C8.3 beta journey and support tickets resolved; C8.4 live low-value purchase/renew/cancel reconciliation; C8.5 release sign-off with open-risk register. |

The performance, RPO/RTO, retention, and support targets must be recorded before C5/C8 sign-off; they cannot be inferred from passing tests. Evidence goes in [delivery status](phase-status.md). The existing [technical roadmap](production-roadmap.md) contains the detailed architecture and earlier phase numbering. This plan is the shorter commercial release gate sequence.

## C0 implementation started

Current slice: require a password at bootstrap, remove the legacy setup-key sign-in API, align CI migration application with the migration directory, and check install-path coverage in repository validation. The isolated PostgreSQL integration suite now exercises C0.1–C0.5, including a 0007→0009 upgrade that preserves a seeded service and succeeds when repeated. CI contains the same schema-upgrade data check, but has not yet run on a remote push. C0 stays in progress until that gate and a release installation review pass.

The security and delivery gates are informed by [OWASP ASVS](https://owasp.org/projects/asvs/), [NIST SSDF](https://csrc.nist.gov/pubs/sp/800/218/final), [PostgreSQL backup/restore guidance](https://www.postgresql.org/docs/18/backup.html), and [WCAG 2.2](https://www.w3.org/TR/wcag/). These are test and review references, not a claim of certification.
